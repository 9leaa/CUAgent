# C2 总结

日期：2026-10-01；分支 `c2-reliability`。按实施前 [技术方案](c2-design.md) 和原计划第 6 节完成。C0-01、C0-02、C1、C2 本地阶段目标已完成；C3 第二人部署、干净环境复现和发布不在本次完成范围。验收结束时未提交；用户随后授权四阶段分别提交和推送，不创建 PR 或发布版本。

## 做了什么、怎么做

专业上是持久控制权、线性化准入、在途/UNKNOWN 对账和独立验收；直白说：人接手或出错时先停住，重新看现场，确认没有重复执行，再把原任务交回模型，预算不能重置。

`c2_bridge.py` 复用 C0/C1 执行器，新增 owner/epoch/session 绑定和独立开发控制通道。停止立即关闭新派发并记在途；有在途或 UNKNOWN 时不能提前接管。重启保留原预算、目标和未决结果，默认暂停，不恢复旧快照或自动重放。交还要求当前人类控制权、新观察、实际目标身份、预算余量与明确新会话；交还后模型必须再次观察，旧会话/epoch/快照拒绝。

model、verifier、control 三种私有能力分开，模型只能操作固定授权应用、窗口、字段和结果文件，不能接管、验证、修改审计或运行任意 shell/网络工具。真实截图仍通过官方 attachment 服务送给原 Harness Agent 循环，不增加第二套模型主循环。文档故障使用真实 NSTextView、人工 GUI 修改、恢复纠正与系统保存面板，不能用改磁盘文件替代。

`c2_fault_audit.py`、`c2_window_audit.py`、实际预算/在途诊断及反例测试分别核对效果、恢复和拒绝。故障诊断、正式评测、计算器与 A0 回归分别建新 run，失败和旧版本全部保留，不拼成同版成绩。C1 观察提示仍默认关闭。

## 证据、限制与交接

私有 `.runtime/runs/c2-faults-report.json`、`c2-formal-report.json`、`c2-formal-independent-audit.json`、`c2-calculator-regression.json`、A0 verification 和 `c2-safety-audit.json` 汇总原始证据。正式 run 为 `c2_formal_<case>_20261001_<001..003>`；七故障 run 与原失败详见 PROGRESS。guest `C0Evidence/<run>` 保留 trace、截图、AX、产物、验证文件；原官方会话和 request-audit 留 host 专用 home。凭证、原截图、完整会话与 VM 不进 Git。

四阶段分支均已创建，每阶段设计和总结均在 `docs/stages/`。验收结束时分支尚无独立提交；用户随后授权按 C0-01 → C0-02 → C1 → C2 整理递进提交。历史 guest 源码用于恢复前序阶段，共享适配器按阶段能力拆分并重新运行本地测试；这不是当时自动保存的完整提交快照，也不改写原始验收证据。实际提交及远端状态以 Git 为准。

VM、用户接受的 VNC 监听和 SSH 保持运行，普通 mvpagent/SIP/零宿主挂载复查通过；无活动 Computer Use executor，结束的任务已冻结，Driver 原权限已恢复。当前官方 App 留在 A0 回归配置，该 run 已耗尽；新的任务必须使用新 run 与明确受控配置，不能继续消耗或清零旧预算。

这不是恶意同用户进程/插件隔离、完整网络零流量或安全认证；VNC 外部可达性未测试，也未因 wildcard listener 改端口或停 VM。C3 的干净源码/无凭证基线、第二位开发者部署和新任务扩展仍未做；A1/O0 后续能力不纳入本次完成声明。
