## 收口前顺序

1. 完成剩余生命周期恢复决策/清理失败检查及最小反例，不能把所有不确定分支写成可自动恢复。
2. 核对1小时最终产物、同session/原预算、等待证据连续性、重启及发布时间门禁。观察器退出或缺报告均不算成功；观察超时不等于进程结束。
3. 1小时通过后再执行8小时；同样保留失败和完整计时证据，不能只看服务还活着。
4. 重读实际证据，写阶段总结，更新README/PROGRESS，核查只提交公开文件，再推送阶段分支及快进默认分支。

长测范围是“草稿→业务等待→同会话最终发布”，不证明模型连续推理8小时、任意GUI长任务或关闭Desktop后的独立执行。P4/P5仍须各自新分支、依据届时证据重写方案；P5一周真实使用不能由本阶段测试替代。C3/第二人继续暂缓。
