# P3 持久执行：结果与限制

2026-10-03，分支 `p3-durable-execution`，初始方案提交 `8268dc1` 先于实现。按 [方案](p3-design.md) 完成当前单人日报任务范围的本地验收；逐项证据见 [验收表](p3-acceptance-audit.md)。GitHub交付状态以README和实际远端提交为准。

## 做了什么

专业说明：持久检查点、租约与epoch隔离、原请求现场核对、分类重试、同会话续接、业务停滞检测和发布时间门禁。直白说：服务重启后知道原任务做到哪了，先查证再接着做，不重复写文件，不重置30次预算；到发布时间才生成最终报告。

仍复用官方Desktop/Harness主循环。后端只调度与核验；模型固定DeepSeek 4.1 Flash/off。迁移0003增加检查点，0004增加release_at。WAITING_RELEASE释放执行资源，等待期间不调用模型；到期重新领取原任务，使用原session、剩余预算及原草稿。只读inspect/poll最多3次、1/2秒退避；有副作用的RPC超时不自动重发。无进展300秒先停止派发，再重新查询现场并按需取消。

## 无模型回归与失败

最终命令：`python -m backend.manage test`（使用项目backend-venv）80/80；`node --test agent/tests/*.test.mjs` 64/64；同版官方注册六文件测试31/31；`python3 -m unittest discover -s agent/tests -p test_daily_report.py` 13/13。后端保留一项TestClient/httpx弃用警告。最后9项断点补测先提交方案`0fb18c4`再实现；它们验证RPC顺序及不重发，不冒充真实进程退出。P3没有重跑真实VM。

失败原样保留：部分产物首试因已知policy终止原因分类遗漏保持UNVERIFIED；首个小时草稿和激活断点首试均漏CSV path，被独立核验拒绝。明确新任务七个CSV字段后另建新轮次通过，未补写模型文件或放宽期望。激活首试17/30、36836 token；失败长测草稿7/30、9818 token；部分产物首试10/30、13959 token。停滞首试测试计时和盲目取消旧idle会话的失败亦保留。更完整过程和其余调用用量见PROGRESS；这些数字不是本阶段总费用。官方未提供可核对的逐任务货币费用，不能用token猜费用。

## 不代表什么

- 长测证明有业务发布时间约束的“草稿→等待→原会话发布”，不证明连续模型推理8小时、任意长GUI任务、关闭Desktop执行或跨机器部署。
- 断连测试是本地任务响应通道故障，不是共享网络/数据库宕机；停滞测试冻结观测，不是服务商模型真实挂起。
- UNKNOWN不自动恢复；缺会话、未知提示接受、未核清副作用仍BLOCKED。测试覆盖声明的决策与反例，不宣称框架任意指令窗口均穷尽。
- 清理失败保留私有pending记录及Worker日志；API尚无独立清理告警字段。业务SUCCEEDED不等于配置恢复成功，按backend/README在App空闲时处置，不重跑业务。
- 单人、单Desktop资源，C3/第二人继续暂缓。P4/P5未完成；P5必须实际一周使用。下一次模型请求前重新查额度，不使用重置卡或积分。
