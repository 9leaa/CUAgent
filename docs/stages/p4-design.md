# P4 效率：先测量，再决定是否启用

2026-10-03，分支 `p4-efficiency`，起点P3已推送`12c0e7f`。本方案先提交，后实现。P4未验收，不将P1既有收益重记为本阶段完成。

## 证据与选择

重新读取P1两个原summary-v2：首轮17/20、327775 token（input51950/output25585/cacheRead250240），确定性排版后20/20、295128 token（53416/17456/224256）；模型轮次总时间153772→135342ms，实际请求196→209，模型工具调用196→189。说明降低模型输出/往返与减少实际工具请求不是一回事，不能只报最好看的指标。P3又出现模型遗漏CSV path，缩短提示不能删掉数据契约。

专业方案是受控只读输入聚合与配对实验；直白说，把原来分几次交给模型的资料合并返回，减少来回说话，但每次实际读文件/统计仍分别扣预算、记审计。模型仍负责理解并生成report.json，确定性工具只统计和排版，不代替模型生成最终业务报告。

候选增加opt-in `workspace_report_inputs`：固定从授权task.json读取任务，再完整读取指定notes、按指定numericColumns统计CSV。返回原task、逐文件完整内容/路径/SHA和完整统计对象，不提供独立oracle或预生成报告。只有P4专用preset/审批允许；原P1/P3默认工具清单、提示、验收和已派发任务保持不变。严禁任意路径、shell、网络及写入。聚合上限与现有任务约束一致，失败/取消/越界立即停止；每个实际内层请求先准入、预算持久化、独立result，不能一个外层调用换免费读取或30次之外的内部动作。输出总量受限，不截断后伪装完整。

## 实施顺序

1. 先做离线配对比较器及反例测试，要求固定完整清单、两臂输入/期望SHA相同、唯一原task/session、Flash/off、失败与返工全部计入。缺usage或人工介入记录不能当0；未完成批次只能报INCOMPLETE，不宣布收益。
2. 复用现有读取、CSV和审批实现只读聚合；先确定外层/内层审计关联及预算约定，再写工具。补停止、30次边界、内层错误、符号链接、审批卸载、原preset不可访问、输出过大反例。验收器仅增加此工具真实读取证据的识别，不改变字段/来源/两产物读回和精确Markdown判据；伪造与缺失内部记录必须拒绝。
3. 新任务显式选择baseline原工具/提示或candidate新preset/聚合提示；不靠环境默认隐式切换。每任务30次原总预算，恢复不清零。先最小受控新候选任务独立核验，再冻结正式配对批次。诊断的失败、费用和介入单独报告，不混入正式成功率或丢弃。
4. 从原固定20类输入模板生成新的两臂任务，逐字节冻结相同输入与oracle。每例各一次baseline/candidate，共40次正式任务，顺序按奇偶交替，串行同App。不得因失败换输入、补跑替换或中途调提示；调参数即保留该批失败并重新决策是否有额度开新批。P1旧报告只是历史参考，不充当本次baseline。
5. 最终报告每例及总成功率、模型调用/实际请求、普通输入/输出/cache-read/cache-write/total token、模型轮次时间与全流程墙钟、人工介入、失败与返工；未知货币费用明确null。记录源码、提示、工具和输入SHA。先逐项证据审计，再README/PROGRESS、总结、提交推送阶段及默认分支。

## 接受或拒绝候选

证据采集补充：直接从原session.jsonl和原审批账本提取每轮usage、工具调用和连续raw计数，不读取可手填的成功summary代替原记录。生命周期控制器另写与run/session及原文件SHA绑定的记录，明确单调时钟起止（激活前至恢复后）、介入事件列表和正常结束标记；缺记录不得补零。业务失败也保留用量，usage缺失或中断未闭合则保持INCOMPLETE。采集器输出指标及安全检查发现，不把指标完整等同业务成功；业务仍重新运行原独立verify。

内部计数契约：外层聚合调用本身计1次（包括失败），task.json读取和每个note/CSV统计再各计1次；这比逐项原调用多1次raw，但减少模型往返，不宣传raw下降。内层callId为外层加固定序号，name仍为workspace_read/workspace_csv_stats，参数摘要、结果SHA及错误按原账本记录。每步重新核对外层许可及取消状态，内层dispatch成功后必须记录一次result（失败也记录），未派发的后续步骤不伪造结果。只读核心通过必需的受审计invoke回调访问文件，不能自行偷偷读盘；先测此核心，再接官方policy服务/注册表。模型没有可指定路径的聚合参数，只接受固定task.json的受限结构；只返回全量数据，最多64KiB，超过拒绝而不截断。

验收接入契约：P4须显式opt-in，仅支持非定时、单轮新任务，不默默改变P3续接。聚合返回的task/notes/csv须逐字节来源及独立oracle匹配；根据固定task顺序推导全部内层callId、参数摘要、返回SHA，要求父派发→内层依次派发/返回→父返回，任何缺失/额外/乱序/错误结果均拒绝。只有此证据核对后，才可把聚合内的真实来源读取交给原业务验收；不修改期望、不代写文件、不跳过两产物完整读回。专用preset仅在新任务明确选择并获审批时使用，默认P1/P3入口保持不变。

基线和候选均至少18/20，零假成功/越权；候选成功数不得低于基线，人工介入不增加。完整40次证据下，候选总token至少降低10%，且总执行墙钟不增加超过10%，才允许作为该任务的默认配置；同时报告非缓存输入与输出，不能把缓存token等同现金费用。若收益不足，保留实验结论，候选默认关闭，不为过关调整阈值；明确P4优化未证明有效。有限样本不宣称普遍可靠性或统计显著。
