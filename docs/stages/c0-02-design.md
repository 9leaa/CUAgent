# C0-02 技术方案

日期：2026-10-01。分支：`c0-02-fixed-ui`。前序：C0-01 真实模型单例及独立验证通过。依据 GitHub 原计划第 4 节，不缩减九例和三种 GUI 任务。

## 目标

同一固定模型、官方 Desktop Agent 循环和测试 VM 下，九个计算器任务及本地表单输入、滚动定位、测试文档保存各真实成功至少一次。每次尝试独立 run-id、目录、30 次 raw 预算；保留失败，不通过固定脚本或模型自算替代 GUI。

## 实施顺序与边界

1. 把 C0-01 固定计算器桥接扩为开发侧选定的任务注册表：表达式、许可按钮轨迹、独立期望值在验证器中预定义，不允许模型传任意表达式/期望值/路径。增加加、减按钮，其余 fresh AX、应用/窗口、持久预算、停止、审计、图片及授权限制不变。
2. 制作 VM 内无外网依赖的固定表单/滚动 fixture，以及任务专用文档目录。先核对已安装 guest 应用与 Driver 的实际工具参数，再选择可访问性可靠的系统浏览器/文本编辑器；不能为方便测试改变宿主应用或使用模型 shell。
3. GUI 桥接按当前任务唯一授权应用和窗口，限制输入字段、输入长度、可选控件及文件位置；所有 Driver 内部调用也计 raw。固定本地页面可由开发侧准备，最终表单填写、滚动与文档保存必须由真实模型观察决策，不能由准备脚本完成。
4. 独立验证器只读受控产物、提交字段/页面状态、文件正文及新 UI 观察；与模型 token 分离。计算器核对完整按钮轨迹、新显示、文件及期望值；表单核对预定字段和提交效果；滚动核对确实滚动到离屏目标后的新状态及目标内容；保存核对模型实际保存轨迹、实际文件内容和新窗口身份。缺任一证据为 UNVERIFIED。
5. 启动器按任务安全关闭上一 run，新的 guest run 与 Host 会话/连接对应；Host 账号/历史保留，不继承旧任务快照或清零旧任务预算。停止和独立验证后的 run 不再用于新任务。
6. 先新增并运行窄边界/mock 测试，再部署 guest，完成真实接口正/负门槛后依次派发真实任务。轮次未结束或进程仍活着时继续观察同一任务，不能因超时盲目重复派发。

## 固定用例及证明

实现选择：表单和滚动使用仓库提供的原生 AppKit 测试界面（仅在 VirtualMac 普通账户运行，无浏览器/外网依赖）。测试文档使用同一原生文本编辑界面及系统 NSSavePanel，最终保存到任务目录；不是 bridge 直接写文件。fixture 只提供 UI、真实提交/保存效果及只读状态记录，模型必须通过 Driver 观察、填写、滚动和点击。保存位置被 fixture 与 bridge 双重限定；不得以“Save 按钮调用成功”代替实际文件及界面核对。

计算器：27+16、8+9、125+75、90−17、50−28、101−1、12×34、7×8、15×6。预定义轨迹由输入数字及运算按钮组成；独立期望值仅进入验证器，每例先 All Clear，新目录写/读 result.txt。

GUI：固定本地表单字段与提交；足够长页面中最初不可见目标的滚动定位；任务专用文本的 GUI 保存。正式运行前固定内容、成功判据及独立期望，不能在看完模型输出后调整验收标准。

保存面板适配（第三次真实尝试前）：Driver 将 NSSavePanel 按钮放在正文 AX 树中，但面板拥有独立 CGWindowID；正文窗口下点击被明确拒绝。仅对同 PID、同应用、唯一可见且标题为 Save task document 的面板，将新正文截图对应的 Save 按钮 AX frame 映射到已核对的面板坐标。面板 AX unresolved 时按 Driver 要求使用 foreground delivery，其他降级仍拒绝；不开放任意窗口、坐标或全局点击。内部窗口清单、面板观察、点击均计入原 30 次预算。拒绝不能记录为完成动作，最终仍须实际文件、新 Saved 状态与独立核对。

第四次尝试前的修正：第三次前台点击也未产生文件。新正文截图确实包含 Save，但面板自己的截图存在父窗口合成，无法支持面板局部坐标换算。改用无降级、真实展示 Save 的正文截图坐标框架，前台点击正文所拥有的 sheet 按钮；仍独立核对 sheet PID、几何和 Save frame，两个范围必须同时包含该按钮。绝不把面板合成截图作为可靠坐标来源。

第五次尝试前：第四次仍未保存，原因尚未确认。去掉中途对 unresolved sheet 的截图读取，避免干扰正文输入坐标缓存；只读窗口清单仍核对面板身份、几何。Driver click 附带任务目录内 debug_image_out 落点图，开发侧据此核对坐标，模型不能传路径；预算不变，实际文件仍是最终门槛。

第六次尝试前：落点图证明坐标指向 Save，但真实保存未发生，缓存猜测未证实。尝试 NSSavePanel 原生 return 确认键，不做自动连击/重试。仅由模型在新观察中选择 Save 后，核对唯一 owned sheet、Save/OKButton（真实 Driver 若未输出 ID 则不能依赖该字段）及限定几何后，允许一次固定 return/foreground，绑原正文 PID/window；模型仍不能调用任意键盘工具。press_key 也计 raw，异常副作用记 UNKNOWN，最终仍须保存轨迹、新状态、真实文件及独立验证。

第七次尝试前：第六次 Driver 明确报告正文无法成为键盘前台目标。将同样的唯一 owned sheet 清单与按钮几何检查之后的固定 return 绑定到面板自身 CGWindowID；执行期间只替换已核对目标，finally 恢复正文 ID，包括失败路径。面板不能聚焦时仍拒绝，不改 Driver、不开放全局 keyboard，不猜任务完成。

第八次尝试前：第七次实际文件、新 Saved 状态和读回匹配，但两次确认键返回被错误地记录成两次完成，独立轨迹 gate 为 UNVERIFIED，报告保留。修正证据语义而不放松完整完成轨迹：Save 的 unverifiable 返回只记 attempted_action；只有下一次新的正文观察确实显示 Saved task-note.txt 且固定实际文件存在，才记录唯一 completed_action/Save，并关联最近的确认尝试快照。仍要求完整 Save Document/Save 完成轨迹、固定输入、文件与独立预期；不自动重放确认键。

运行报告逐次记录 case/run/session、模型/环境版本、状态、耗时、实际 raw 次数、人工介入次数、失败分类、guest 原始证据路径；失败不删除。九例和三例都至少真实一次通过，安全负例通过，才写阶段总结并进入 C1 分支。C1 前后各三次和 C2 18 次门槛不以本阶段结果替代。
