# C0-01 技术方案

日期：2026-10-01。分支：c0-01-computer-use。依据：GitHub harness-migration 的 Harness_Development_Plan 第 4 节；不变更 C0-02、C1、C2 的要求。

## 目标与结构

真实 Harness 模型只收到任务 12×34，不收到期望值。模型根据测试 VM 内 Calculator 的新截图及 AX 观察选择按钮；完成后写入、读回 result.txt。独立验证器核对成功动作轨迹、新显示、文件、预算与预存期望值。只有全部吻合才 SUCCEEDED。

复用官方 Desktop 0.2.0-rc.2 的模型与 Agent 循环，不增加第二个模型循环。Host 插件仅向固定 VM 地址发出受控请求；Driver、路径判断、目标判断、最终派发、安全账本、截图和验证报告全部在 guest。模型不得调用宿主桌面、Shell、通用文件、网络、插件安装或验证接口。

## 实施顺序

1. 保留现有脏文件，不提交/推送；核对 GitHub 原计划、VM 状态和运行时。既有开发 VM 仅用于本机开发，不作为无凭证发布基线；不读取或复用其中旧模型配置。
2. 定位 guest Python；缺失则安装固定、用户目录隔离的解释器。通过已授权 SSH 单独传输审查后的程序，不挂载宿主目录，不复制模型凭证。
3. 部署 guest Task/HTTP 桥接：Calculator bundle/PID/窗口绑定；每动作需要新鲜且未消费的观察；白名单按钮；超时 UNKNOWN 不盲重试；每任务 30 次实际请求，停止/审计错误 fail-closed，恢复不清零；跨进程单例。
4. 完成真实 HTTP 正/负测试，模型 token 与独立验证 token 分离，错误参数/其他目标/预算/停止均拒绝。验证与真实任务各用新 run-id，测试不消耗正式任务账本。
5. 增加专用 C0 Harness 工具及 preset，独立配置与编译产物，不覆盖 A0 验收账本。仅观察、点击、写结果、读结果；图片必须是真实模型内容块；取消信号须传到 guest stop。
6. 通过官方 Desktop 会话运行真实任务；保留每次尝试，不能用固定脚本替代模型操作。独立验证接口仅由开发侧调用，验证返回不泄露给执行模型。
7. 完成后写 c0-01-summary.md，记录改动、版本、命令、证据、失败及未测项，再进入 C0-02 分支与技术方案。

## 验收与证据

- 当前普通账户、SIP、共享挂载、Driver 权限及新截图；VNC 使用用户明确接受的现有监听方式，不声称公网暴露或仅本机。
- 本地无 VM/mock 与真实 guest/HTTP 测试分开；到限不得再观察，给最终验证预留预算。
- 正式任务：模型真实 call/result，成功清空及输入 1、2、Multiply、3、4、Equals；操作后新显示；result.txt 写入及读回；独立验证 SUCCEEDED，实际原始请求不超过 30。
- 失败/歧义/未完成调用不会被算成功；审批拒绝/停止不得换入口绕过。原始截图及轨迹留 guest 私有任务目录，公开源码只记录脱敏总结。
- C0-01 单例通过不代表整个 C0、C1、C2 完成。后续仍按原计划九例和三个界面任务、六类增强、18 次可靠性评测及全部安全门槛执行。
