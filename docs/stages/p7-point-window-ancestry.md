# P7：点击命中元素的严格窗口归属解析

2026-10-15；继续未完成的 `p7-expense-reconcile`，不是新阶段。先提交本方案，再实现和验证。017终止证据保留，不恢复旧会话。

## 依据与边界

017的系统命中查询、PID读取成功，AXWindow为NoValue，直接窗口查询为IllegalArgument。当前缺失角色和命中PID日志，不能假定命中的是Calc文本元素，也不能证明父链一定可解。

固定上游 `platform-macos/src/ax/exact_target.rs::element_window_id` 已有40层父链，但其 `owning_window_id` 会把AXSheet映射到父窗口。这适用于背景目标归属，不适用于本次屏幕遮挡保护，禁止直接复用。全局点命中入口仍唯一；禁止改成应用局部命中、仅PID匹配或矩形包含。

## 实现契约

1. 把解析策略抽为可注入节点读取的纯核心，生产适配使用拥有引用的AX节点；不复制上游主循环，不改正式Driver安装。
2. 系统命中元素先取PID；后续每个被使用的节点（包括AXWindow属性目标、父节点）均须验证同PID。任何读取错误、类型异常、空角色、跨PID立即拒绝，不能继续爬到目标窗口放行。
3. 当前直接AXWindow路径保留，但检查属性目标角色：仅AXWindow或AXSheet可取其自己的CGWindowID。首个窗口/Sheet就是终点，非零ID必须精确匹配请求窗口；不把Sheet改映射为父窗口，不越过不匹配窗口继续向上找。
4. 仅明确无AXWindow值/不支持该属性时进入有界父链。先检查命中元素自身角色；若自身就是窗口/Sheet则取自身编号，否则取AXParent。最多40个节点、CFEqual识别循环；无父节点、循环、超限、AXApplication边界均拒绝。限制一次解析总时长，使用当前元素范围的AX调用超时，不能更改系统级AX超时；一旦超时不得发送输入。
5. 每个成功复制的CF引用由RAII释放，异常路径和循环也释放；纯核心不得持有裸CF引用。最终仍经原 `deliver_if_matching` 精确比较PID/窗口并仅投递一次；之后原有新截图核验不变。
6. 私有诊断只保存命中PID、固定角色、路径类型、深度和AX状态/窗口编号，不保存元素文本。原错误字段保留，父链失败另给明确原因。解析证据并不保证后续事件接收者，检查与投递的竞态限制仍公开保留。

## 验证矩阵

- 成功：直接窗口属性、命中窗口自身、缺属性的多层同PID父链；均只投递一次。
- 拒绝：其他应用、同应用其他窗口、Sheet自己的编号不同、跨PID属性目标或父节点、未知角色、属性异常类型、AX读取错误、窗口零ID/错误码、缺父、Application边界、自环/多节点环、超过40节点、超时。每项断言零动作；不得通过绕过首个窗口来找正确祖先。
- 边界：恰好深度上限和多一层；读取次数与上限一致；错误不重试；所有引用释放。通过移除精确窗口比较与跨PID拒绝的反向测试证明断言有效，再恢复原代码。
