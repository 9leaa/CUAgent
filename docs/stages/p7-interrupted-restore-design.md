# P7 中断后的原配置恢复

2026-10-07，先方案后实现。原第三例已失败收尾，不能重跑；本步骤仅恢复原 Harness 配置，不解除隔离、不恢复 Worker、不关闭未核验文档。

可信本地入口持原共享桌面锁，核对原 quarantine、失败收尾意图及其输入摘要、原 task/session/run/owner/epoch、唯一已结束 Attempt、无成功产物、空闲资源与无在途任务。重新查询官方原会话 terminal 和 guest stopped/零在途/预算不变；所有缺证据情况拒绝。

复用已有生命周期命令，按 stop-restore → profile restore → start-restore 顺序执行。命令本身复核所有官方会话空闲、App 身份、原 profile 前后 SHA、原预置和独占副作用意图。恢复总意图提前独占保存；失败只留脱敏阶段、隔离与原状态，结果不明禁止自动重发。成功后独立读回 profile 原 SHA、guest 停止和预算不变，再记录私有回执。

本入口不激活模型、续租、重置预算、创建任务、声明业务成功、移除 quarantine、关 TextEdit 或启动旧 Worker。后续监听/隧道与隔离收尾须独立核对，不能将 profile 恢复等同整个环境恢复。

测试覆盖正常有序恢复、会话仍运行、在途调用、预算变化、原身份/证据变化、资源占用、未完成 Attempt、旧恢复意图及每阶段失败；失败不得继续下一阶段或清除隔离。使用模拟 App/guest 与隔离数据库，实机恢复另留回执。

## 原监听和隧道收尾

配置恢复之后，可信操作者持原共享锁，重验恢复回执与活动profile摘要、原DB失败状态、原官方会话terminal和原guest身份/停止/零在途/9raw，再记录独占shutdown意图，单次调用既有DesktopControlClient.shutdown。独立SSH确认原guest PID退出、原控制端口和模型端口均无监听。响应不明先只读核对，不能重发或强杀。

原宿主SSH隧道只能在其原端口、完整命令及启动时间均匹配时正常TERM；事后确认原PID消失和本地原端口释放，不按名字批量清理，不强杀。全部前后证据及人工介入保存在新的私有回执，原失败、调用预算和文档不变。缺业务核验的TextEdit暂时保留；本步骤仍不移除隔离或启动Worker。

## 隔离对账与原Worker恢复

仅在原失败已终态、App/profile恢复、原guest/隧道/TextEdit退出且文档SHA不变后进入。持宿主原共享锁，独立SSH复查进程/监听及guest共享锁可取得，所有原队列无待执行任务/资源空闲、原P5源码摘要不变、官方全部会话空闲且预置与原恢复回执一致。原scheduler许可须由既有revoke入口撤销，不授予未来任务。

独占保存对账意图及全部证据摘要；原quarantine采用无覆盖硬链接存入原run后核对inode与字节，再移除活动路径，失败记录保持UNVERIFIED，原隔离字节可恢复。此举表示已清除残留执行风险，不表示中断根因已修复或业务验收通过。释放共享锁后只恢复原仓库/原环境的单个backend.worker，独占启动意图，核对其PID/命令持续存活、取得原共享锁且队列仍空；启动不明只查原PID，不创建第二个进程。P5 API/调度器不在此操作范围，不补跑漏期。
