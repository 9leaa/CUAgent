# P1 可核对日报技术方案（实现前）

分支：`p1-daily-report`，2026-10-02。依据 [产品路线](../product-roadmap.md)。第一项采用此前推荐的资料整理＋CSV 日报：给用户一个真实可运行入口，保持模型/Harness 工具链，后续由 P2 Worker 调用相同任务协议。

## 输入和结果

任务输入为选定日期、UTF-8 Markdown 进展记录和 CSV 文件；源目录只读，准备器复制到新专用工作区并记录 SHA-256，不让模型接触个人目录。Markdown 使用项目标题及“进展”“阻塞”“下一步”三个固定标题，标题下内容可变化；CSV 数值列由提交者明确选择。第一版针对这个输入合同，非法/歧义输入在提交前报错，不声称任意文档理解。

任务 workspace 内包含 task.json、inputs 下的快照及模型写入的 report.json/report.md。task.json 说明目标、输入路径、数值列与输出合同，不含独立期望答案。模型读取文件、调用已有 CSV 统计、整理完整记录与来源、写两份报告并读回。JSON 包含日期、每份记录的标题/进展/阻塞/下一步/来源 SHA、每个 CSV 的完整统计和来源 SHA。Markdown 使用固定可读格式，内容与 JSON 一致，不能以正确 JSON 掩盖错误说明。

准备器仅准备输入与独立 oracle，不生成执行产物。验证器独立读取原始源快照，用独立 CSV 解析/统计核对每个字段、Markdown、两份完整读回、输入未变、实际模型工具轨迹与策略账本。只有全部通过才 SUCCEEDED；模型 finished 不算成功。生成器不能复用被测统计实现构建 oracle。

## 实现边界

复用 A1 六工具和持久 30 次预算、session/root 隔离；权限针对目录/路径/类型/大小而非固定正文答案。新增框架无关 prepare/verify/报告合同模块和 CLI，不引入后台调度或新主循环。执行由官方 Desktop RPC 创建独立会话，私有配置明确绑定会话/目录/账本。API 地址/cookie 从现有项目私有运行环境读入，凭证不入源码、标准输出或公共报告。

当前 A1 配置最多 20 个任务，批次只在所有旧轮次 idle 后切换，保留旧三任务及原账本；必要时分批配置而不是扩预算。启动/轮询均保存官方原事件与模型身份、usage、工具调用及错误；中断状态未知先查同一 session，不直接新建补跑。任务 CLI 后续可被后端调用，不用每个任务重新写脚本。

## 验证方案

先测试输入校验、Unicode/多行/空字段、重复标题、CSV 引号/缺失值/负数/小数、路径逃逸、结果篡改、缺读回、假成功与预算完整性。公开测试只用合成资料，无凭证。

真实评测在首次模型调用前冻结 20 组不同合法输入、顺序、SHA 和预期，至少 18/20 通过、零假成功；所有失败留存，不替换失败 run。变化覆盖多项目、中文/英文、零值/负值/小数、缺失数值、引号/逗号、不同列顺序及文本长度。另列非法输入拒绝，不把拒绝凑入 20 个成功样本。统计真实 calls、usage、耗时与人工介入，货币成本无来源则 unavailable。

完成后 README 给可复制的准备/执行/查询/验证命令；公开脱敏结果与失败原因，私有证据留在忽略目录。先完成并验证 P1，再开 P2 分支写后端方案。单人条件不阻塞，真实使用一周等长期门槛保留后续阶段。
