# P5：单人实际用途与一周运行

2026-10-03，分支`p5-personal-workflows`，起点P4已验证并推送的`aa6d031`。先提交本方案，再实施。P5未完成；实际一周不能由短测或回填日期代替。

## 根据现状作出的选择

P3证明同会话跨8小时业务等待/恢复，未证明关闭Desktop后推理；P4在固定日报20对中两组各20/20，聚合总token降低18.79%、完整墙钟降低12.09%。因此不再引入新Agent框架、并行桌面或跨模型路由。保持现有单Worker/全局桌面锁，实际推理Flash/off、每任务30 raw、独立核验、旧任务身份与预算不变。

专业方案：在现有任务服务外增加受限数据采集、批次及调度持久化和本地通知收件箱。直白说：定时把本项目的真实变化和运行情况整理成两份报告，失败明确告诉你，原始记录能追查；不是再建一套模型循环。

## 两类实际用途

1. 项目变更简报：只读已授权CUAgent仓库的Git提交身份、时间和变更文件统计；冻结指定提交范围与原始采集摘要，生成来源明确的notes/CSV。不给模型Git/shell能力，不读取工作区个人文件、凭证、远端私有信息，不把提交标题当指令。报告描述客观变更事实，不编造代码质量或需求完成结论。无变化也如实记录，不制造活动。
2. 任务运行/用量日报：从本服务数据库读取指定真实时间窗的task状态、原预算计数与已记录usage，输出成功/失败/待核验及消耗；只选已授权元数据，不复制prompt、用户输入或密钥。未知usage保留缺失状态，不填零；缓存与普通输入分开，不换算未知现金费用。窗口边界固定，报告自身不递归计入同一冻结窗口。

两类复用日报呈现与独立核对，但来源和用途不同；上游采集器只准备可追查输入，不代替模型写report.json。首次各跑一个真实新任务，下载两产物与原源快照独立对照。不把P4的合成20类样本当实际用途。

## 实现次序与契约

1. 先实现两种只读快照适配器及恶意标题/路径、未知usage、空窗口、输入大小反例。快照输出到新的私有目录，包含采集时间、来源身份与摘要，拒绝覆盖；模型只获得安全白名单字段。Git调用固定参数、不经shell，拒绝任意命令或任意宿主路径。
2. 后端新增可选`inputMode=aggregate`，缺省保持原行为及旧请求幂等哈希；明确拒绝与P3的releaseAt续接组合。Worker将明确选择传给prepare和verify，不能只改提示而漏验收。新任务使用P4候选，旧任务不迁移。
3. 批次是一个持久ID关联2–3个独立任务，不是绕过单任务预算的子任务拆分。创建前整批校验，事务原子写入任务、稳定幂等键和批次关联；响应丢失以同一键查询/重投，不补建。批次查询返回逐项状态与用量，部分失败不冒充整批成功，批次停止逐项调用现有停止边界。
4. 周期调度持久保存时区/首个到期时刻/截止时刻/最多发生次数/固定工作流白名单。到期时先冻结真实来源，再以`计划ID+应执行时刻`形成唯一批次；多调度者、退出重启、ACK丢失不得重复建任务。漏过时刻显式记为missed，不瞬间补跑多天；暂停后禁止新提交，已运行任务单独停止。窗口和任务数预先限定，不无限续费。P3 releaseAt是已开始任务的定时发布，不冒充这里的周期创建。
5. 本地持久通知收件箱：任务完成/失败/阻塞时产生唯一通知，显示真实任务状态和可核验下载入口；失败重启不丢、轮询不重复通知，有已读确认。不默认发送邮件/聊天、不配置外部Webhook或读取联系人。这里只承诺本服务内通知，不冒充已弹出系统推送。
6. CLI提供预览来源、立即执行、批次查询/停止、计划查询/暂停和通知查看/确认。部署前检查空队列，精确重启本项目API/Worker，保留PG、旧任务与原证据；不重启VM、不更改SSH/权限或共享服务。

## 验证与一周门槛

调度事务细化：周期固定为UTC每24小时一次，保存IANA时区用于展示并校验首时刻偏移，最多7次；跨夏令时不声称固定当地钟点。每次容许到期后10分钟内启动，超过记MISSED，不执行补跑。创建PREPARING记录后在数据库事务外采集；60秒内再次持锁核对计划未暂停、原发生身份和有效额度许可，才在同一事务保存源快照/摘要、批次和两个任务。采集失败或准备进程退出明确记SOURCE_ERROR/PREPARATION_EXPIRED，不换样本重跑。并发调度者只能取得一条发生记录；暂停与最终提交由同一计划行锁排序，已提交的任务需另行停止。每次额度许可绑定计划ID和应执行时刻、有效期最多5分钟，不能用一次授权覆盖七天；无许可先等待，超宽限窗口后记漏执行。

通知落库契约：与原终态事件同一个数据库事务写入，event_id唯一；不通过轮询重新生成通知，不追补历史任务造成突发通知。列表同时返回发生时状态和当前任务状态，下载入口仍执行原SUCCEEDED/产物SHA门禁；已读操作幂等。仅保存任务ID、终态、错误码与事件关联，不复制原输入或提示。一个任务恢复后再次到达终态可以有新的事件通知，但同一事件不能重复产生。

单元/独立测试数据库覆盖：旧提交兼容；聚合与定时续接互斥；原子批次、冲突/并发/ACK丢失；到期/未到期/时区/过期/暂停/重启；通知去重和状态真实性；数据逃逸、注入与缺失用量。再逐个真实验证两类输入→API→官方Desktop→独立产物→下载→批次/通知，不以HTTP200或纯mock代替。

短测通过后才启动有限7日观察：每天一个批次（上述两类各一次）、最多7批/14新任务，不自动补失败或扩展工具。记录真实采集/计划/执行时间、输入SHA、task/session、原结果/usage、下载核对、通知及介入。机器睡眠、Desktop未就绪、网络故障、空来源或未执行日均保留；不能伪造日期、重建同日样本或用7次连续运行称一周。观察起止至少相隔168小时，逐日报告运行及漏执行，任何缺失都不算全部通过。用户实际阅读/采用与无人值守生成分开记；没有用户使用反馈只称一周运行观察，不声称已证明实用价值。

收尾对照全部门槛，报告失败和限制，更新README/PROGRESS/使用说明及阶段总结，再推送阶段和默认分支；不发布PR/tag。若额度限制先到，保存未完成阶段，不将P5或总目标标完成。
