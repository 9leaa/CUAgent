# P3 持久执行：基于 P2 证据重新制定的方案

2026-10-02，分支 `p3-durable-execution`，起点已推送 P2 `6bd8c4a`。本方案先提交，再写代码。用户要求后续阶段重新思考；不直接把路线表当实施方案。

## 判断与目标

P2 两个真实日报都只需约十秒、9/30 请求，证明短闭环和幂等提交可用，不证明长时间恢复。现有断点很具体：activate 写独占文件后失败不能重试；create 与 prompt 分成多次 RPC，中间死亡无法知道是否已派发；Worker 重获 epoch 时只改磁盘审批，正在运行的插件仍绑定旧 epoch；一次 RPC 失败立即 BLOCKED；五分钟总超时不是无进展检测。因此先解决执行状态与真实现场的一致性，再做时间验收，不能靠不断跑日报或空转计时冒充长任务。

专业上增加持久状态机、只读 reconciliation（现场核对）、fencing（旧执行者隔离）和可观测检查点；直白说：记录“做到哪了”，重启后先看原会话和文件，再决定接着查、补做尚未发送的步骤，还是停下来。

## 实现顺序与限制

1. 检查点：为每个任务保存阶段、原 session、原 prompt requestId、审计总数/摘要、已存在产物摘要、更新时间与无进展计时。检查点由 Worker 写，模型不能改；审计账本仍为预算权威，不能用 checkpoint 覆盖或清零账本。恢复时检查旧审计必须仍是前缀、文件只允许预期新增，不接受回退或静默篡改。
2. 观察接口：runner 增加纯只读 inspect，返回 session 是否存在/运行、原 requestId 是否入库、原轮次结束、实际工具数和有限进展标识。请求或观察超时不等于原任务结束。没有官方证据时 UNKNOWN/BLOCKED，不重新提交 prompt。
3. 分类恢复：准备/配置/创建/选模型/发送 prompt/执行/核验/恢复基础配置均分开记录意图和结果。只读 RPC 可有限指数退避；创建、prompt、写入不得盲重试。原会话仍在运行时先撤销旧派发、取消并确认停止，不直接改 epoch 让旧会话继续动。已终止且有完整报告可独立核验；确证尚未发送 prompt 才发送一次。部分产物只有读取、SHA 和轨迹核对后，才可在同 session 用剩余预算发显式续接，不覆盖已有文件、不新建任务绕过 30 次。
4. 无进展：以新 turn/tool/结果和检查点为进展，不把心跳当业务进展。默认可配置无进展期限，触发先停止派发、查询现场、取消原请求，留有错误码与证据。等待外部条件的状态有明确唤醒时间/截止时间，不无限续租。
5. 生命周期：跨进程文件锁仍覆盖整个 Desktop 控制生命周期；恢复基础配置也要记录成功/失败，不能业务 SUCCEEDED 就吞掉清理失败。数据库掉线时执行端租约到期拒绝后续请求。API、Worker 和 Desktop 存活分别报告，不用 /health 推断整体成功。

模型全程 DeepSeek 4.1 Flash/off，不引入额外模型；不扩大宿主工具权限，不改 VM/网络/个人服务；C3/第二人仍不做。

### 配置激活后、创建会话前的恢复补充

`active-tasks.json` 存在只证明尝试过配置，不证明已创建或发送任务。恢复须同时满足：创建/创建响应/模型选择/提示/续接意图文件均不存在；原检查点前缀有效、审计为空、没有报告产物；官方只读 inspect 明确原 session 不存在。满足后以新配置文件 rebind 当前 epoch，不覆盖旧激活记录；rebind 自身仍只执行一次、失败不重试。再次核对会话不存在，才进入已有 start 的唯一创建/发送流程；start 还会检查同 workspace 无会话。任何缺失字段、身份不符、现场已有 session、RPC 不可达或已有副作用均 BLOCKED，不根据缺失响应重发。补充正常路径及每项拒绝反例，真实断点另留证据；不能把 mock 当作真实恢复通过。

### 真实失败后的输入契约提示补充

长测首试和激活断点首试均出现模型复制CSV统计对象时漏path；工具实现实际返回该字段，不能归因于恢复丢数据。原提示仅说“完整对象”，现为新任务明确列出path、rowCount、columnCount、columns、numeric、bytes、sha256全部字段，要求首次写入前核对，不新增调用或提供统计答案。字段值仍来自真实工具，不由后端补写业务JSON；已有失败文件不可覆盖、验收规则不放宽。普通和定时草稿提示共享此契约，已派发的长测及历史prompt不改写。新真实断点用相同输入另建唯一任务，保留前次失败/费用，不宣称一次成功证明普遍可靠性。

2026-10-02 真实部分产物测试补充：控制文件先停止派发、再调用官方 cancel，下一模型请求可能先被 A1 guard 拒绝；官方首轮 reason 实际为 error/UNKNOWN/“A1 request policy unavailable”，并非 aborted。第一例因此保留 UNVERIFIED。续接验收只额外认可此精确的已知策略拒绝边界，不认可其他任意 error；仍须原会话/账本前缀不变、无未返回调用、所有实际工具成功且完整匹配、两产物各一次写入和最终完整读回。不能靠改变 expected 或忽略失败工具来通过。

## 验收顺序

先不耗模型：真实 PostgreSQL 检查点/领取/故障事务测试，同版工具注册验证过期/停止/旧 epoch、预算跨恢复不减；纯恢复决策表覆盖每个意图和响应之间的断点、历史审计被截断/更改、重复结果以及部分文件。各断点必须明确“允许哪一步”和“禁止哪一步”，不以所有分支都 BLOCKED 代替恢复功能。

再最少量真实 Flash/off：在已创建未发 prompt、已发 prompt 未记录确认、产生第一个产物、完成未登记成功四个窗口退出 Worker；重新启动后观察原 session，验证只有原任务/账本、每份产物最多一次写入、剩余预算不增加。只对本项目进程注入退出；断连用任务专用 RPC 故障注入，不停共享网络或数据库。所有失败与介入保留，不能只汇总最终重跑成功。

最后先 1 小时，再 8 小时真实经过时间：安排明确业务等待/检查点与有限工作段，执行中途恢复并在结束后独立核对；任务最多 30 次原总预算。长时间服务存活、原任务可恢复、期间业务推进分开计数；单个十秒任务成功后空等不算 1/8 小时长任务验收。若现有日报不足以定义有意义的长任务，应补充一个受控的分阶段资料汇总模板及固定输入/期望，再测，不用批量独立日报替代原任务连续性。定时观察程序可保留私有运行证据，最终按单调时钟与真实现场证明时长，不能加速时钟或由单测代替。

时间门槛未到时 P3 保持未完成，不提前推送“已验收”的 README。阶段代码通过短测可有中间提交，但只有完整门槛通过才阶段收口并同步默认分支。额度接近本次上限则保留状态停止，不消费重置卡/积分；观察等待不需要持续调用模型。P4 与 P5 在 P3 证据明确后各自重新写方案，一周使用也必须实际经过。

## 长时间用例细化：到点发布日报

四个短任务故障窗口已真实验证后，采用同一任务的“草稿→等待发布时间→最终发布”，不以独立日报批量替代连续性。提交可选带时区 releaseAt；第一轮只允许生成 report.json 并读回，不生成最终 report.md。工具执行层绑定不可变 publishNotBefore，提前 renderer 拒绝，普通 write 在此模板只能写 report.json，不能绕过期限写 Markdown。该限制进入账本身份，恢复不能修改期限。

草稿经独立预检且会话停止后，持久状态 WAITING_RELEASE，保存原 session/账本/产物检查点，停止执行租约、释放资源并恢复基础 App 配置。等待不调用模型、不占无限续租；API 可查待发布时间、可停止，但不能以 resume 绕过时间。独立 Worker 到期领取同一任务，再核对旧证据、原预算和现场后续接，只生成缺失 Markdown 与两次完整读回；只有最终核对通过才提供成功产物下载。过期时钟与提前发布必须反例覆盖。

先短时间完整验证接口及执行端门禁，再真实 1 小时、通过后再真实 8 小时。私有观察程序用单调时钟采样数据库状态、原账本摘要、文件不变及 API/Worker 存活；每轮中途实际退出/重启 Worker，API 至少一次重启，到期后原 task/session 成功及每个产物仅写一次。1/8 小时以实际草稿等待与最终恢复全程记录为证据，明确这是“有业务发布时间约束的持久任务”，不是模型持续推理8小时或任意长 GUI 任务的证明。若该范围不足以覆盖最终目标，报告未覆盖项而不偷换声明。
