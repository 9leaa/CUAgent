# P7 费用核对：实施前方案

2026-10-08。用户要求先不处理P5、继续向前；在独立分支`p7-expense-reconcile`推进下一工作流的设计及离线开发准备。原`p7-project-handoff`工作区、冻结候选008和任务不改动。原路线要求交接验收后进入下一项，本轮仅提前准备，不将上一项标为通过；费用真实执行仍须独立准入。此文件先于费用实现，不是验收报告。

## 做什么

给Agent一组专用测试票据和交易流水，让它找出哪些能对应、哪些缺票、哪些重复或金额不一致，在VM表格应用整理结果。不是报销系统，不转账、不提交报销、不访问个人银行或真实财务数据。

专业描述：来源绑定的对账结果契约，使用确定性十进制验证器独立复核。
直白说：每一笔结论都能找到原票据和流水；程序另算一遍账，不能只相信模型说“对了”。

## 输入与规则

- 可信调用方提供固定测试材料清单：1–20笔交易、1–20份测试票据、币种CNY和明确核对日期。原PDF/图片的SHA、大小和来源ID冻结；模型不能给任意路径或URL，不从模型文字推断文件可信。
- 交易CSV固定列`transaction_id,date,merchant,amount,currency`，ID唯一，日期严格YYYY-MM-DD；金额为十进制字符串（如`123.40`），最多两位小数，严格正数，上限999999.99。初版不含退款、外币、税率和汇率；这些输入明确拒绝，不能静默丢弃。
- 票据原图/PDF是原始依据。离线开发可使用人工审核的提取记录进行算法测试，但必须标为测试输入，不得冒充OCR或模型看图完成。每条提取记录绑定原文件SHA、页码、字段及清晰/模糊状态；模糊金额或日期进入待确认，不猜值。
- 首版只支持一笔交易对应一张票据。日期和金额相同只形成候选，不自动证明匹配；商户文字原样保留，不做隐含模糊归一化。多候选标歧义，拆单/合单列为不支持并待确认。
- 重复文件SHA和重复票据号码分别标示，不直接删除原材料，也不把同金额同日期直接认作重复支出。号码缺失不杜撰。
- 初版总额分别统计交易总额、唯一已确认匹配交易总额和未解决交易总额，三者满足守恒；票据总额单独列出，不能将重复/模糊票据混加后宣称差额确定。

## 结果及独立验证

每笔交易必须恰好出现一次，状态为`matched`、`missing_receipt`、`amount_mismatch`、`ambiguous`或`needs_confirmation`；每份票据也必须有归属或明确未匹配原因。结果绑定完整输入SHA及原run/session，引用只能指向冻结来源。

验证器检查覆盖完整、ID存在、一对一关系、来源摘要、字段事实及金额重算。使用Decimal解析并换算整数分，不允许float、NaN、指数写法、隐含四舍五入；重复计入和伪造总计均拒绝。差额方向固定为交易金额减票据金额。模型解释的语义与票据提取正确性单独验收，结构/算术通过不等于语义或GUI通过。

交付是对账表、异常清单和汇总（可同一工作簿三个sheet），以及来源索引。所有单元格作为文字或受审查的数值写入；以`= + - @`开头的来源文本必须按应用明确的纯文本机制处理，未证明有效前禁止导入。不要只加一个单引号就假定任何应用都安全。

## 开发顺序与边界

1. 离线输入契约、拒绝反例和整数分金额核对；独立模块，不开放API/Worker或模型工具，不读取任意用户文件。
2. 结果契约、来源覆盖和金额验证；测试预期人工列明，不用被测算法生成自己的答案。冻结正常、异常、歧义三组完整测试材料与审核标准。
3. 只读核实VM内可用表格应用及版本、AX能力、保存/重开/单元格类型；未核实时不指定已支持应用。缺应用需另获安装授权，不改用宿主个人应用。
4. 应用适配和受限工具审查，保持原30raw、停止、独占租约、失败审计与UNKNOWN不重发；实际内部调用全计数。先测真实动作成本，若完整输入/保存/重开/读取无法在30raw完成，停止并调整设计，不放宽预算或偷偷拆会话。
5. 固定版本、原材料与验证器，在服务和实时额度准入后跑真实模型/VM。模型保持deepseek-account/deepseek-flash、reasoningEffort=off。真实业务文档只能由VM GUI产生，离线验证器不得代写它。
6. 独立读取原工作簿的单元格/类型和实际文件，再与GUI重开新观察、完整结果和下载副本核对。保存成功提示不是验收证据；未知文件格式先明确拒绝。记录所有失败、未测和用量，README/PROGRESS区分开发、真实验收、用户采用，验证后提交推送。

## 最小测试矩阵

| 场景 | 必须得到的结果 |
|---|---|
| 0.10与0.20累计 | 精确0.30，无浮点误差 |
| 两笔同日同额、两张候选票据 | 歧义，不能任意配对 |
| 重复SHA或号码、缺票、未匹配票据 | 原件均保留且问题显式列出 |
| 模糊OCR日期/金额 | 待确认，不构造确定金额 |
| 金额不符 | 差额方向与整数分重算一致 |
| 重复交易、未知ID、漏项、伪造来源/总额 | 验证拒绝 |
| 控制字符、公式文本、超限、float/NaN/外币 | 按契约拒绝或保留为纯文本，不能执行 |
| 停止、租约丢失、30raw耗尽、保存响应未知 | 禁止继续派发或盲目重放，保留原失败 |
| GUI保存重开及下载 | 单元格、类型、原文件及下载一致，否则未验收 |

当前仅完成方案；费用模块、票据样本、应用能力和真实验收都未完成。P8仍在三项工作流完成之后，不提前宣称进入产品易用性验收。
