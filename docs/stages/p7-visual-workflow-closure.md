# 截图任务闭环与跨应用验证

目标：截图定位、动作、动作后观察、文件保存、重新打开及独立读回全部有证据。Calc、文本编辑器和浏览器采用同一观察/动作边界，应用语义验证允许分别实现；不以单例或mock通过代替跨应用验收。

## 顺序与验收

1. 新建原始任务复验654a048：新快照重新解析名称框，完成聚焦、输入、提交、打开保存面板。021不重放；保留30次实际请求上限、停止与UNKNOWN规则。
2. 在当前截图确认实际保存面板结构后，补绑定路径填写、最终保存、重新打开动作。每步独立观察；唯一新文件路径来自可信任务绑定，拒绝覆盖，保存前再次核对父目录身份。模型不得自行选择任意路径或修改验证器。
3. 独立只读验证器读取该ODS文件，核对工作表和A2的精确文本。限制ZIP大小、解压量、条目数、XML大小及重复行列展开；拒绝DTD、外部实体、加密、重复成员、符号链接及公式单元格。不得创建或修改工作簿，不算GUI完成证据。最终验收必须另外关联真实GUI保存轨迹、重新打开截图与任务身份。
4. 逐步去除语义动作的AX硬前置：截图定位配合准确窗口归属、遮挡和新鲜度检查；AX可用则辅助。不得用猜坐标替代缺失观察，也不得放宽动作后验证。跨软件用文本保存与本地浏览器表单作为独立用例，使用同一模型/Driver/预算，记录失败及人工介入。

## 真实保存面板发现缺口与修复方案

2026-10-17开发侧仅打开Save面板检查，未保存、不计模型通过。CGWindow当前清单确认同Calc PID426的独立窗口85、layer8、430×374；原Driver默认list_windows漏掉该窗口，显式get_window_state(426,85)取得Save截图及完整文件名/目录/格式/Save控件。不能用底下窗口53的快照与索引操作该面板，也不能仅凭另有系统面板服务进程推断窗口归属。

拟为Driver的list_windows增加显式include_accessory_windows选项，默认不变；开启必须给定正PID，只发现该进程当前可见的各层窗口。不依赖AX窗口可解析性来过滤，Space字段无法确认时保留null。返回候选不授予操作，仍需新快照、独立进程身份、原文档关联及精确窗口/遮挡检查。跨进程面板仍需独立关联证据，不自动放行。Linux/Windows对该macOS专用选项明确拒绝，避免静默退化。以纯边界测试和固定工具链构建核验候选，再做VM观察验证；不以mock或发现窗口替代最终保存/重开。
