# 从工程原型到个人任务服务

2026-10-02 用户授权执行本路线：每阶段新分支，先技术方案、再实现、验证、同步 README/PROGRESS 后推送 GitHub。C3 和所有第二人复现暂缓。当前复用官方 Desktop/Harness 主循环，不再建第二套 Agent 循环。

目标：单人可提交、查询、停止和恢复任务，后台能连续工作数小时，结果有证据、错误可定位、用量可统计。后台服务运行、单任务推进和关闭 Desktop 后执行分别验证；第一版保留 App/Host 就绪依赖。

| 阶段 / 分支 | 交付 | 验收 |
|---|---|---|
| P1 / p1-daily-report | 指定资料目录＋CSV 的可核对日报；任务内容与执行权限分离 | 派发前冻结 20 组不同输入，至少 18 组实际模型通过，失败有原因、零假成功；不以代码生成报告替代模型工具链 |
| P2 / p2-task-service | FastAPI、PostgreSQL、SQLAlchemy/Alembic、独立单 Worker；提交/查询/停止/恢复/事件/产物/用量 | 重复提交不重复建单，API 重启不丢任务，同一 VM 单执行者；一次真实任务从提交到下载独立通过 |
| P3 / p3-durable-execution | 检查点、心跳、执行权、分类重试、无进展检测 | 先 1 小时再 8 小时；注入进程退出/断连，预算连续，无重复副作用；现场核对后恢复 |
| P4 / p4-efficiency | 先基线再上下文、图片、确定性工具、缓存与模型对照 | 固定同批任务报告成功率、总用量、耗时、人工介入；失败和返工计入，不降低判据 |
| P5 / p5-personal-workflows | 增加 2–3 类实际用途，再接定时、批处理、通知 | 连续一周真实使用记录后决定扩展范围；观察时间不能由单元测试替代 |

Harness 管任务内部推理；后端管权限、预算、排队、状态；Worker 管执行生命周期；工具层执行并拒绝越权；独立验证器决定成功；数据库保存关联与索引，产物/原始证据单独存储。模型不能写审计和验证结果。

P2 先以 PostgreSQL 短事务领取队列任务，执行期间不占数据库事务。数据库锁不能代替 VM 互斥，执行端必须拒绝过期执行者。Redis/Celery 按实际调度需求再选。日志关联 task/run/session/attempt/call，保存耗时、错误、用量和证据引用，不记录凭证。后续按需要接本地 OpenTelemetry，不重新启用第三方会话上报。

检查点包括已验证成果、待办、产物和剩余预算；恢复重新检查现场。UNKNOWN 副作用先核对，不因 call_id 或队列重投直接重放。当前每任务总计 30 次实际工具请求，恢复/重试不清零；长任务若需新总预算，应在阶段方案与派发前固定，不能用不断建子任务绕过。

效率优化先记录真实 usage，cache 与普通输入分开、缺货币价格就报告缺失。确定性计算交给工具，模型处理理解与异常；新鲜观察绑定仍保留。历史图像可退出上下文但不删除证据；只有固定任务集证明收益才默认启用。

本次资源约束：开始时套餐已用 30%，剩余约 70%；额度耗尽前留收尾余量停止，不使用重置卡或积分。分阶段检查账户用量，长时间验证须可停止并保存进度，不能因本轮额度停止而标完整路线完成。
